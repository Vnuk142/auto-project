# Фанты для двоих — Telegram-бот + Mini App

Готовый исходный проект: **Python 3.11 / aiogram 3.34 / aiohttp / PostgreSQL 15 / Telegram Stars / Nginx HTTPS**.
Интерфейс на русском языке, тёмная тема, игра 18+, задания для двух участников, три уровня, таймер 60 секунд.

> **Статус:** исходный код, тесты и конфигурация подготовлены. Telegram-платёж, реальное открытие Mini App,
> HTTPS и Docker необходимо проверить на собственных токене, домене и сервере. В среде генерации не было
> подключённого Telegram-бота и Docker, поэтому результат не заявляется как проверенный боевой деплой.

## Персональный бесплатный доступ владельца

В Render (Environment) установите **FREE_USER_IDS** = числовой Telegram ID владельца.
Узнайте его командой `/myid` у бота (или через доверенный Telegram ID-бот).
Можно указать несколько ID через запятую. Не используйте никнейм, username или токен
вместо числового ID. До подтверждения 18+ доступ закрыт и для владельца.

Только для перечисленных ID:
- все три уровня доступны без покупки и без списаний Stars;
- `/api/me` показывает нулевые цены и `free_access=true`;
- API заданий открывает средний и смелый уровни;
- команды `/buy_medium`, `/buy_hard`, WebApp и pre_checkout не должны выставлять/принимать платёж;
- остальные пользователи оплачивают medium=50 ⭐ и hard=100 ⭐.

FREE_USER_IDS не даёт прав администратора для возврата платежей (для этого отдельная
переменная ADMIN_IDS). Бесплатный тариф Render и тестовая база Render PostgreSQL —
отдельный вопрос: бесплатная БД истекает через 30 дней и не является постоянной.

## Бесплатный тест на Render

Для Render используется `WEBHOOK_MODE=true`, Postgres Free (30 дней) или постоянная база Neon, встроенный HTTPS без Nginx. Смотрите `DEPLOY_RENDER_IPHONE.md`. Основная ветка действующего проекта не затронута.

## 1. Быстрый старт

На VPS с публичным адресом установите Docker Engine с плагином Compose, настройте DNS A-запись домена на IP сервера.
Нужны открытые порты **80/tcp и 443/tcp**, права на запись в текущую папку, установленный `openssl`.

```bash
cd fanty-bot
cp .env.example .env
nano .env
```

В `.env` обязательно заменить `BOT_TOKEN`, `WEBAPP_URL`, `DATABASE_URL`, `POSTGRES_PASSWORD`, `ADMIN_IDS`.
Пароль в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD`; для пароля со спецсимволами применяйте URL-кодирование.
`WEBAPP_URL` должен совпадать с публичным HTTPS-адресом, который введён в @BotFather.

### Сертификат для первого теста (самоподписанный)

```bash
mkdir -p certs
openssl req -x509 -nodes -days 7 -newkey rsa:2048 \
  -keyout certs/privkey.pem -out certs/fullchain.pem \
  -subj "/CN=your-domain.com" \
  -addext "subjectAltName=DNS:your-domain.com"
chmod 600 certs/privkey.pem
```

Самоподписанный сертификат пригоден **для локальной технической проверки**, например `curl -k https://your-domain.com/health`.
Он **обычно не принимается Telegram Mini Apps** и не подходит для боевой оплаты — для Telegram используйте
доверенный публичный сертификат Let's Encrypt. Не пытайтесь вводить `http://` в BotFather.

### Let's Encrypt для продакшена

На чистом VPS, **до запуска Nginx**, получите сертификат (укажите свой домен):

```bash
sudo apt-get update && sudo apt-get install -y certbot
sudo certbot certonly --standalone -d your-domain.com \
  --agree-tos -m admin@your-domain.com --non-interactive
sudo cp /etc/letsencrypt/live/your-domain.com/fullchain.pem certs/fullchain.pem
sudo cp /etc/letsencrypt/live/your-domain.com/privkey.pem certs/privkey.pem
sudo chmod 600 certs/privkey.pem
```

Для продления **нельзя одновременно занимать порт 80 Nginx и certbot --standalone**. Порядок:

```bash
docker compose stop nginx
sudo certbot renew --standalone
sudo cp /etc/letsencrypt/live/your-domain.com/fullchain.pem certs/fullchain.pem
sudo cp /etc/letsencrypt/live/your-domain.com/privkey.pem certs/privkey.pem
docker compose up -d nginx
```

Автоматизируйте эту процедуру на хосте через cron/systemd с корректным рабочим каталогом;
проверьте `sudo certbot renew --dry-run` перед включением автопродления.
**Не храните приватные ключи в Git:** `certs/*` включён в `.gitignore`.

### Старт контейнеров

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f bot
curl -fsS https://your-domain.com/health
```

Ожидается `{"status":"ok"}`. `db` не публикует порт наружу, бот слушает `8080` только во внутренней Docker-сети.
Один процесс запускает long-polling aiogram и HTTP aiohttp. Для корректной работы держите **одну реплику** бота.

## 2. BotFather: создание и Mini App

1. В Telegram откройте **[@BotFather](https://t.me/BotFather)** → `/newbot` → задайте имя и свободный username, оканчивающийся на `bot` → скопируйте токен в `.env` как `BOT_TOKEN`.
2. Отправьте `/mybots`, выберите вашего бота → **Bot Settings** → **Menu Button** либо команду `/setmenubutton` → выберите бота → укажите название `🎲 Открыть игру` и **точный** `https://your-domain.com`.
3. В `Bot Settings` проверьте параметры **Payments / Stars** (названия экранов могут меняться). Для цифровых товаров используется **XTR**: сторонний платёжный провайдер не требуется.
4. Для тестов используйте отдельный тестовый бот и **Telegram test environment**, описанный в официальной документации Stars. Экран Payments → Test, если он есть в вашей версии BotFather, не равнозначен тестированию боевых Stars; убедитесь, что тестовый токен и клиент относятся к одному тестовому окружению.
5. Найдите своего бота, отправьте `/start`, подтвердите 18+ кнопкой. После этого появится reply-клавиатура **«🎲 Открыть игру»** и **inline-кнопка запуска**. Reply-кнопка создаёт новое сообщение с inline WebApp-кнопкой. Проверьте также Menu Button.
6. Узнать свой `ADMIN_IDS`: отправьте боту `/myid`, затем вставьте результат в `.env`; при нескольких администраторах используйте запятую.

## 3. Как устроена игра

- `/start`: при первом входе требуются явное подтверждение 18+ и запись `age_confirmed_at`; при отказе — `age_declined_at` и блокировка нового подтверждения в течение 24 часов.
- `/api/me`: проверяет Telegram `initData` (HMAC-SHA256 + срок 24 часа), возраст и активные покупки.
- `easy`: бесплатен только после 18+.
- `medium`: **50 Stars** по умолчанию, `hard`: **100 Stars**; оба доступны только с записью `successful_payment` в PostgreSQL.
- Выбор «Для него» / «Для неё» показывает случайный фант. Кнопка «Подтвердить выполнение — старт (1 мин)» запускает обратный отсчёт; «Стоп / Далее» останавливает текущий отсчёт и выбирает следующий фант.
- Любое действие по взаимному согласию; игра не требует выполнения задания.

**Важно:** наборы фантов находятся в `bot/tasks.py` и передаются в Mini App через защищённый `POST /api/tasks`.
Если поместить все 60 платных заданий прямо в общедоступный `web/app.js`, то любой посетитель сможет прочитать их исходный текст без платежа. Из-за этого применяется серверная проверка прав, а `tasks` в JavaScript — динамический кэш уже разрешённого уровня.

### Платежи

Из Mini App покупки открываются через `POST /api/buy`: сервер отправляет Stars-инвойс прямо в личный чат с ботом, после чего Mini App закрывается.
Это работает и из Menu Button. **`Telegram.WebApp.sendData` доступен только при открытии Mini App из ReplyKeyboard**, поэтому `webapp_data.py` предусмотрен для совместимости с такими клиентами. При этом ReplyKeyboard WebApp может не получать `initData`, поэтому основная клавиатура использует текстовую кнопку, которая выдаёт inline WebApp-кнопку с подписанным `initData`.

Чат-команды: `/buy_medium`, `/buy_hard`, `/myid`, `/paysupport <описание>`.

Алгоритм оплаты: `sendInvoice(currency="XTR")` → `pre_checkout_query` (проверка цены, возраста и наличия покупки, ответ с 6-секундным тайм-аутом на БД) → `successful_payment` → запись `telegram_payment_charge_id` в `purchases.charge_id` → доступ.
Для Stars `provider_token` **не передаётся** по актуальным требованиям Telegram Bot API; передавать пустую строку не требуется.

Администратор может выполнить `/refund <charge_id>`; бот вызовет `refundStarPayment`, затем установит `refunded_at` в базе. Возвращённая покупка больше не даёт доступ. История платежей сохраняется, после возврата повторная покупка допустима.
Повторное получение того же `successful_payment` обрабатывается идемпотентно. Второй реально списанный платёж за уже активный уровень бот пытается автоматически вернуть.

### Изменение цены

Меняйте `PRICE_MEDIUM` и `PRICE_HARD` в `.env`, затем `docker compose up -d --force-recreate bot`.
API `/api/me` передаёт актуальные значения фронтенду. Старые открытые инвойсы с устаревшими ценами отклоняются на pre-checkout.

## 4. Тесты и диагностика

В виртуальном окружении Python 3.11+:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pytest -q
```

Можно прогнать через уже собранный образ: `docker compose run --rm bot pytest -q`.
Тесты покрывают валидную подпись, подмену hash, просроченный auth_date, отсутствие hash, некорректную query string, повторный ключ, чужой токен, битый JSON и дату из будущего, а также 60 фантов.

Диагностика:

```bash
docker compose ps
docker compose logs --tail=100 bot
docker compose logs --tail=100 nginx
docker compose exec db pg_isready -U fanty -d fanty
curl -sS https://your-domain.com/health
```

При `401` для `/api/me`: устаревший `initData`, Mini App открыт вне Telegram или подпись не подходит токену бота. При `403`: не подтверждён возраст или закрытый платный уровень. При `502` на покупке: Telegram не принял сообщение / бот не может отправить личное сообщение.

## 5. Принятые решения

1. **Исходный HTML не был приложен:** в поле `<ORIGINAL_HTML>` получен лишь текст «ВСТАВЬ СЮДА ПОЛНЫЙ КОД…». Сохранить дословно оригинальные 60 строк, прежний DOM/CSS и алгоритм таймера было технически невозможно. Созданы **новые 60 фантов** (по 10 на комбинацию), работающий аналог минутного таймера и новый тёмный интерфейс. **Сверка с оригиналом не выполнена.** Чтобы восстановить первоисточник, замените `bot/tasks.py` и при необходимости оформление и логику `web/`.
2. В отличие от формального требования разместить массив со всеми фантами в публичном JS, платные задания находятся на сервере для защиты контента от простой выгрузки из кода браузера.
3. Пользователь подтверждает возраст **самостоятельно**. Это не юридически достоверная верификация даты рождения и не защищает от ложного подтверждения.
4. Возрастной отказ блокирует подтверждение на 24 часа. После истечения 24 часов пользователь сам вызывает `/start`.
5. API-путь покупки — основной; `sendData` запасной. Важное техническое отступление от ТЗ: **ReplyKeyboard WebApp заменён на текстовую ReplyKeyboard-кнопку, которая выдаёт InlineKeyboard WebApp**. Официально Telegram не гарантирует `initData` при прямом открытии из ReplyKeyboard. Иначе строгая проверка HMAC запретила бы игру с такого входа. Варианты входа с корректным `initData`: inline WebApp и Menu Button.
6. Схема БД создаётся через SQLAlchemy `create_all()`; автоматические миграции не внедрены. Уникальный частичный индекс PostgreSQL запрещает два активных доступа к одному уровню.
7. `MAX_INIT_DATA_AGE_SECONDS=86400` и допуск времени клиента +60 секунд. Дубликаты параметров и неверный JSON отклоняются.
8. Контакт поддержки в `SUPPORT_CONTACT`; команда `/paysupport` также пересылает описание проблемы администраторам `ADMIN_IDS`.
9. Содержимое игры — романтические и доверительные задания без откровенного порнографического описания. Telegram может ограничивать доступ к приложениям с тематикой 18+; перед публикацией проверьте действующие правила платформы и применимое законодательство.
10. Одна реплика long-polling. Для горизонтального масштабирования нужны дополнительные механизмы распределения обновлений, rate limiting и webhook.

## 6. Известные ограничения и эксплуатационные риски

- Telegram Stars, полученные ботом, обычно доступны для вывода через **Fragment** после выдержки **21 день** и при доступном остатке не менее **1000 Stars**; требования и способы вывода могут меняться. Проверяйте состояние баланса и актуальные правила Telegram.
- Возрастная самоаттестация **не является надёжной проверкой 18+**. При необходимости законной возрастной проверки используйте отдельный проверенный механизм, соответствующий юрисдикции.
- Контент с маркировкой 18+ может повлечь жалобы, ограничения Telegram / магазинов приложений и блокировку бота. **Возрастной баннер сам по себе не гарантирует соответствия правилам.** Незаконная публичная порнография запрещена правилами Telegram.
- Бот не может автоматически подтвердить факт тестового/боевого списания без связи с API Telegram; внешние платежи необходимо проверять на реальном токене.
- Если Telegram выполнил возврат, но БД упала до отметки `refunded_at`, администратор должен вручную сверить состояние оплаты и доступ. Аналогично надо обработать возможные сетевые сбои после успешного платежа.
- После отзыва/смены `BOT_TOKEN` старые `initData` перестанут проходить проверку, пользователям нужно переоткрыть Mini App.
- `create_all()` не обновит старую схему при изменениях моделей; перед такими релизами внедрите Alembic и резервное копирование.
- Лимиты и правила Telegram могут измениться; обновляйте зависимости и проверяйте обратную совместимость перед каждым релизом.

## 7. Чек-лист приёмки

- [ ] `/start` без 18+ не выдаёт игровую клавиатуру; API также блокирует игру
- [ ] `initData` проверяется HMAC-SHA256, есть минимум 5 тестов
- [ ] `easy` доступен бесплатно после 18+
- [ ] `medium` и `hard` открываются только после `successful_payment`
- [ ] `telegram_payment_charge_id` сохраняется в PostgreSQL
- [ ] Повторная активная покупка уровня отклоняется
- [ ] `pre_checkout_query` получает ответ за 10 секунд на реальном соединении
- [ ] Таймер, кнопки «Для него» / «Для неё», «Подтвердить», «Стоп / Далее» работают
- [ ] **Если получен оригинал HTML:** проверено буквальное совпадение всех 60 фантов и прежнего таймера
- [ ] HTTPS-домен, DNS и Nginx настроены с доверенным сертификатом
- [ ] Тестовая оплата через Telegram test environment / Payments → Test успешно пройдена
- [ ] Проверены повторная доставка `successful_payment` и `/refund`
- [ ] Проверены Menu Button и reply-кнопка на iOS и Android
